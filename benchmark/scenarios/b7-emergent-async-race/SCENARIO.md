---
id: b7-emergent-async-race
class: emergent
severity: MAJOR
one_line_defect: aggregate() reads each metric's running bucket, awaits an async normalize, then writes bucket+1 back — but runs the iterations concurrently via Promise.all(map(...)), so every same-metric iteration reads the identical pre-await bucket and their writes clobber one another, collapsing N samples into 1.
reproduction: node reproduce.mjs
why_no_single_line: The bucket read (`?? { sum: 0, count: 0 }`), the `await normalizeSample(...)`, the fold-and-write, and the `Promise.all(samples.map(async ...))` concurrency idiom are each individually correct and idiomatic. Nothing is wrong on any single changed line; the lost update exists only in their interaction — a read-modify-write of shared state that is split across an await while iterations run concurrently, so reads observe stale state and later writes overwrite earlier ones.
correct_finding: Report that aggregate() performs a non-atomic read-modify-write of `totals[metric]` across the `await normalizeSample(...)` boundary while iterating concurrently under `Promise.all(map(...))`. All same-metric iterations execute their synchronous read before any resume past the await, so they all read the same bucket and the last write wins — samples are dropped (counts collapse to 1 per metric, totals are not conserved). Ground it by running `node reproduce.mjs` (cpu count reads back 1 instead of 3, total 2 instead of 5) or by naming the invariant: an accumulator mutated across an await must be sequenced, or the read+write must be atomic with respect to concurrent iterations.
---

`aggregate` normalizes samples concurrently with `Promise.all(samples.map(async (sample) => { ... }))`. Inside each iteration it reads the metric's current bucket, `await`s the async normalizer, then writes back `{ sum: bucket.sum + value, count: bucket.count + 1 }`. Because `map` runs every callback's synchronous prefix (the bucket read) to completion before any callback resumes past its first `await`, all iterations for a given metric read the SAME initial `{ sum: 0, count: 0 }`. When they later resume and write, each overwrites the previous write instead of building on it, so a metric that received N samples ends with `count: 1` and only the last sample's value. Totals are silently under-counted — a data-integrity defect, not a crash.

The fix is to make the accumulation atomic with respect to the await. Either sequence the loop so each read-modify-write completes before the next begins (`for (const sample of samples) { const value = await normalizeSample(sample.value); ... }`), or split the phases — do all the awaited normalization first, then fold synchronously (`const normalized = await Promise.all(samples.map(async (s) => ({ metric: s.metric, value: await normalizeSample(s.value) }))); for (const { metric, value } of normalized) { ... }`). Both keep the concurrency where it is safe (the normalization) and remove it from the shared-state update.

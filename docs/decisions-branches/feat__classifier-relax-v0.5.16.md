## 2026-05-26 17:24 - Relax classifyPerSkillOutcome for natural bot phrasings (v0.5.16, 1F)

**Reasoning:** Pre-v0.5.16 classifier required literal "0 findings" / "0 finding" / "n/a" to mark a per-skill check-run success. Natural phrasings the bot actually uses ("0 critical findings", "no findings to anchor", "zero performance findings", "not applicable", "✓ all anchored") all classified as failure. Caused recurring false-positive per-skill check-run fails on every clean PR with strictSkills set (which is exactly why PR #73 reverted this repo strictSkills to []). v0.5.16 broadens the success regex with three new patterns: quantifier+modifiers+finding (0/no/zero + 0-3 modifier words + finding(s)), explicit "not applicable", and ✓ checkmark as universal clean signal. Hard-failure override (\\b[1-9]\\d*\\s+(?:\\w+\\s+){0,3}finding) catches positive finding counts BEFORE success checks fire so the existing "10 findings" regression test from PR #57 still passes. 8 new tests in test/skills.test.js cover both new acceptances and new failure preservations.

**Alternatives considered:** Enumerate skill-specific synonyms (e.g. "pattern fights" for respect-existing-conventions, "contract breaks" for api-contract-enforcement). Rejected: whack-a-mole; better to encourage canonical "0 findings" wording in the bot prompt AND give a universal escape hatch (✓ checkmark). Documented as limitation. Also considered: ship classifier relaxation + prompt update to require canonical wording. Deferred prompt change to 1G when lib/prompts.js gets extracted; piling more prompt edits onto inlined templates is the kind of churn 1G is meant to eliminate.

**Implications:**
- Future strictSkills adopters (especially dedicated-mode skills via clud-bug add) get cleaner per-skill check-run signal — no more false-positive failures from natural phrasing. v0.6 App will use the same classifier when it emits per-skill check-runs from N parallel Claude calls; false-positives there are louder because each false fail = wasted user attention on a paid review. Composite pin bumped @v0.5.15 -> @v0.5.16 per release-discipline lock-step rule (test/release-discipline.test.js enforces).

## 2026-08-24 09:01 - Adopt TypeScript 7 on dev, fix the #295 job-rename test break, and repair the corrupted file-structure.md tree root

**Reasoning:** main bumped typescript to ^7.0.2 via Dependabot and has been CI-red since 2026-08-12 because TS7 hard-removed esModuleInterop:false (tsconfig.json still set it, guarded by an ignoreDeprecations:6.0 escape hatch that itself only existed to suppress that exact deprecation). Adopting TS7 on dev directly — rather than waiting to inherit main's broken state via merge — means dev never goes red and the tsconfig diff that would otherwise conflict on merge disappears. Separately, #295: PR #288 pinned test/skills-base-ref.test.js to the job name clud-bug-review; PR #292 (2026-08-07, post-SPEC-2.0) deliberately renamed that job to review and added a new gate job so the API-posted clud-bug-review check-run is the sole producer of that name (fork PRs can't self-post a check, so the job's own green conclusion could no longer double as it). The decision log at docs/decisions-branches/fix__fork-checks-neutral.md confirms this was intentional, so the template is correct and the test was stale — fixed the test's REVIEW_JOB constant to 'review', not the template. Third, docs/file-structure.md's committed tree was rooted at a worktree directory name (wt-294) with .merge_file_* temp files captured in — logmind's tree-root comes from cwd's basename, which is wrong inside any git worktree (not just this one); regenerated it from a plain filesystem copy of the tree placed at a directory literally named clud-bug so the walk produces the correct root, matching what CI's check-derived-docs job (a normal actions/checkout, not a worktree) would produce.

**Alternatives considered:** Downgrade dev back to TS6 to dodge the break — rejected per explicit instruction: Dependabot will just re-open the same bump, and dev would inherit the same red build the moment main merges in., Point REVIEW_JOB at 'clud-bug-review' by renaming the template's job back — rejected: the rename was a deliberate SPEC §6.5 fix for fork PRs going green having reviewed nothing; reverting it would reopen that hole., Run logmind file-structure --write directly in this worktree — rejected: cwd basename is the worktree's own directory name (confirmed empirically), which is exactly the corruption this fix removes; regenerating in-place would just re-produce it under a different wrong name.

**Implications:**
- esModuleInterop and the now-dead ignoreDeprecations:6.0 escape hatch are gone from tsconfig.json entirely (TS7's default interop behavior applies, and the full build + 1146-test suite + 5 fixtures are green under it with zero other compile-error fallout across dev's newer lines). test/skills-base-ref.test.js's REVIEW_JOB constant is now a documented pointer at the template, not an independent assumption — a future rename will fail loudly there again if the constant isn't updated alongside it. docs/file-structure.md is root-correct and picked up 3 file entries (render-ci.mjs, fork-notice.yml.tmpl, skills-base-ref.test.js) that the corrupted version never had. The underlying logmind worktree-root bug itself is NOT fixed by this PR — it's tracked separately (orchestrator backlog #53) since it needs a fix in the logmind tool, not in this repo.

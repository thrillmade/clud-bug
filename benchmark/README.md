The **launch gate** for retiring the manual adversarial panel. It measures whether
clud-bug's hardened review catches bugs that live on **no single changed line** —
the class the old *"quote the exact diff line or drop"* gate silenced.

## Why

Three real bugs a manual panel caught but clud-bug missed (logmind #169/#165/#171)
shared one property: no single changed line is wrong. The bug is **emergent** (bad
data through individually-correct lines), a **combinatorial invariant breach**, or
**cross-cutting** (the cause is in another file the diff only exposes). A reviewer
that can only cite a diff line has nothing to cite. The fix (Phase R): accept a
**reproduction** or a **named violated invariant** as grounding equal to a quoted
line. This benchmark proves the fix works.

## Structure

`scenarios/<id>/`
- `module.mjs` — the "PR under review" (self-contained, runnable with plain `node`,
  the planted defect in a form where no single line is obviously wrong).
- `reproduce.mjs` — `node reproduce.mjs` demonstrates the defect (`BUG CONFIRMED` +
  exit 1 when present; `ok:` + exit 0 if fixed). This is the ground truth a
  **maintainer** runs to confirm the scenario is real. SPEC 2.0 §4.7 bars a
  reviewer from executing code, tests, builds or scripts at all — a reviewer
  never runs this, and is scored on whether its findings locate the planted
  site instead.
- `SCENARIO.md` — the **answer key** for a human (class, severity, the invariant,
  the correct finding). Withheld from reviewers during scoring.
- `answer.json` — the same key for the scorer: the planted site (`file` +
  `lineRange`, plus `acceptAlso` for a cross-cutting defect's second correct
  site) and whether a correct review reports a `finding` or stays `clean`.
  Withheld too.

A `clean` scenario is correct code with a bug-prone *shape*; flagging it is a false
positive. The `s*` scenarios are the regression cases from the real misses (logmind
#169/#165/#171); `b*` are diverse true-positives; `c*` are decoys. **See
`RESULTS.md` for the per-scenario scoreboard.**

## Running

Confirm every scenario reproduces a real bug:
```bash
for d in scenarios/*/; do node "$d/reproduce.mjs"; echo "  ($d exit=$?)"; done   # buggy → exit 1, clean decoys → exit 0
```
Score the recipe against the whole corpus — materialises each scenario as the
two-commit repo the Action would review, runs a headless reviewer over it with the
tool allow-list, model, thinking budget and review prompt all read out of the JS/TS
workflow template (every scenario is a `module.mjs`, so that is the one `clud-bug
init` would install here; the file it read is recorded in `config.workflowTemplate`),
and scores the structured output against `answer.json`. Scenarios run in a seeded
order that interleaves the planted defects and the decoys, so a run stopped for cost
leaves a sample of both halves rather than a prefix of one; the seed defaults to the
run id and is always recorded. What that reviewer is *not* given — PR context, `gh`,
the inline-comment tool — is recorded in the result file's `invocation` and printed
with the score:
```bash
npm run build                                          # the runner imports from dist/
node scripts/run-benchmark.mjs                         # needs ANTHROPIC_API_KEY; --cost-cap-usd overrides its cap
node scripts/run-benchmark.mjs --dry-run --out /tmp/b  # plumbing only, no key, no network
node scripts/render-benchmark.mjs                      # republish every claim above
```
`.github/workflows/benchmark.yml` runs the same two commands on a schedule and opens
a PR with the result.

## The launch-gate criteria (Option B — hard-gate)

The manual panel comes off — and only then do we launch — when ALL hold:
1. **Seeded benchmark ≥20** planted MAJOR/MED-HIGH across all 3 classes (incl. these
   originals as regression cases) → **100% of MAJOR, ≥90% of MED-HIGH** caught, each
   catch grounded in one of SPEC 2.0 §4.2's three forms: a diff line quoted verbatim,
   a named CI check that already ran against the commit and failed, or the named
   invariant the change breaks — never a reproduction the reviewer ran itself (§4.7).
2. **10 consecutive** trigger-surface PRs where clud-bug's blocking set ⊇ the panel's
   (any miss resets to 0).
3. **≤1** false-blocking MAJOR across those 10.
4. **Zero** silent downgrades (no later-confirmed-real bug emitted only as a watch-item).
5. CI-evidence floor: on every PR the reviewer reads every check that ran against the
   commit under review (§4.7's default — `src/core/ci-checks.ts`; a repo narrows it
   with `ciChecks` and switches it off only with an explicit empty array), and a bug
   on no single changed line is grounded on a failed check or a named invariant
   rather than dropped for want of a line to quote.

**Re-arm:** any recipe/skill bump that regresses this benchmark re-opens the gate.
The corpus size the gate is measured against is the one the block above names.

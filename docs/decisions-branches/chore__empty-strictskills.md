## 2026-05-26 16:44 - Revert strictSkills to empty array (was misconfigured)

**Reasoning:** PR #59 set strictSkills to the 4 baselines (critical-issues-only, evidence-based-review, respect-existing-conventions, clud-bug-collaboration). But baselines are all review_mode: shared — they run as ONE bundled Claude call, not independent calls. Per-skill check-runs are then derived by grepping the bot Per-skill scan block for each baseline line — meaning each check-run gates on whether the bot wrote literal "0 findings" for that line. The classifier (classifyPerSkillOutcome in lib/skills.js) requires exactly "0 findings" or "n/a"; bot phrasings like "0 critical findings", "no findings to anchor", "0 pattern fights" all fail. Result: 2-3 false-positive per-skill check-run fails on every PR with a clean review verdict. strictSkills was designed for DEDICATED-mode skills (where each entry is an independent Claude call worth gating separately). With 0 dedicated skills installed here, the right value is []. Master clud-bug-review check (strictMode: true) still gates on critical findings — that semantic is preserved.

**Alternatives considered:** Keep current 4-baselines config + fix the classifier to accept more phrasings ("0 critical findings", "no findings to anchor"). Rejected: classifier-too-literal is a v0.6 polish item but the underlying design tension (per-skill check-runs derived from one bundled call) remains. Better to align config with design intent now and revisit classifier when dedicated-mode skills are installed and actually need the gate. Also considered: keep current. Rejected: every PR fails 2-3 per-skill check-runs on grammar not substance — noise crowds out real signal.

**Implications:**
- Going forward this repo gets only the master clud-bug-review check-run from clud-bug. Per-skill check-runs will reappear if/when a dedicated-mode skill is installed (e.g. clud-bug add thrillmot/agent-skills/brand-voice-review would add a brand-voice-review check that gates on an INDEPENDENT brand review pass). Eliminates the recurring classifier-false-positive noise without losing real signal. CHANGELOG implication: README should clarify that strictSkills is for dedicated-mode skills, not baselines.
